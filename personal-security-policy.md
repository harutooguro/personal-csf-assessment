# Personal Security Policy

**Version:** 1.0  
**Effective date:** 2026-10-04  
**Owner:** Haruto Oguro  
**Review cadence:** Semi-annually

## Purpose

This policy translates the governance thinking of NIST CSF 2.0 and 
ISO/IEC 27001 into a lightweight set of rules I follow in my own 
digital life. It is intentionally short and operational, not aspirational.

It exists because the current state assessment made one thing clear: 
technical controls (2FA, encryption, backups) decay quickly without 
rules that keep them in place. This document is the "Govern" layer 
that sits above the technical actions in the remediation plan.

## Scope

This policy covers all personal digital assets catalogued in 
`01-asset-inventory.md` — hardware, accounts, and data — across both 
US and Japan contexts.

Out of scope: institution-controlled assets (college-provided Microsoft 365, 
landlord-provided network infrastructure) are treated as third-party 
dependencies, with endpoint controls as compensating measures.

## Core Principles

1. **Minimum attack surface** — Fewer accounts, fewer apps, fewer 
   permissions.
2. **No single point of failure** — Critical access must have a 
   recovery path that does not depend on the same device or channel.
3. **Phishing-resistant where possible** — Prefer passkeys and 
   authenticator apps over SMS.
4. **Confidential by default** — Treat untrusted networks as hostile; 
   treat shared devices as untrusted.
5. **Living document** — This policy is revised when it stops matching 
   reality, not kept pristine.

## Account Management Rules

### New service registration

Before registering for any new online service:

- Password: Generated by password manager, 16+ characters, unique.
- 2FA: Enabled at registration if the service supports it. Preferred 
  order: passkey / security key > authenticator app > SMS.
- Recovery: Recovery email and phone must be current before leaving 
  the registration flow.
- Scope check: If the service only offers SMS 2FA for a sensitive 
  account (financial, identity), reconsider whether to use it.

### Credential hygiene

- Password reuse is not acceptable for any Critical or High priority 
  asset.
- Password manager master password is memorized, not stored anywhere.
- Recovery codes for Critical accounts (Apple ID, Google Account, 
  bank, GitHub) are stored offline.

### Session and access review

- Quarterly: Review active sessions and connected third-party apps 
  on Apple ID, Google Account, and the primary bank.
- Quarterly: Review trusted devices and prune unused ones.

## Data Management Rules

### Classification

- **Critical** data (identity documents, financial records, career 
  vault) must be encrypted at rest and backed up with at least one 
  independent copy.
- **High** data (academic records, project materials) must be backed 
  up but may rely on a single cloud copy.
- **Medium / Low** data has no mandatory handling rule.

### Backup verification

- Monthly: Confirm that the MacBook backup ran successfully.
- Semi-annually: Perform a dry-run restore of at least one critical 
  file set.

### Sharing and AI tools

- Information shared into any AI tool (ChatGPT, Claude, Gemini) is 
  treated as potentially retained by the provider. Legal names of 
  third parties and account numbers are not entered.
- Public GitHub repositories must not contain any real credentials, 
  real email addresses tied to accounts, or specific physical 
  locations.

## Network Rules

- Home Wi-Fi is treated as untrusted — endpoint controls (VPN, 
  encrypted DNS, device firewall) must be relied upon rather than 
  network-layer trust.
- Public Wi-Fi: VPN or iCloud Private Relay required.
- Auto-join of open networks: disabled.

## Incident Response

If any of the following occurs, follow the escalation steps below:

| Trigger | First action |
|---|---|
| iPhone missing > 30 minutes | Mark as Lost in Find My; change Apple ID password from another device |
| Suspicious login alert on Apple ID or Google Account | Change password; review session list; invalidate backup codes |
| Suspected SIM swap (loss of signal + unexpected service calls) | Call carrier from alternative line; freeze port-out; review financial accounts |
| Unauthorized financial transaction | Call bank fraud line; dispute transaction; rotate credentials |

A dependency list of iPhone-bound 2FA accounts is maintained 
separately so that recovery is possible if the phone is unavailable.

## Review Cycle

- **Monthly checks** (15 minutes): Backup status, login alerts, any 
  policy violations noticed during the month.
- **Quarterly review** (1 hour): Access reviews, password manager 
  audit, third-party app pruning.
- **Semi-annual review** (2 hours): Full CSF Protect / Detect 
  re-assessment; update this policy and the remediation plan.

## Accepted Residual Risks

The following risks are acknowledged and accepted rather than 
remediated:

- **Shared home Wi-Fi** — Compensated by endpoint controls (VPN, 
  firewall, treating network as untrusted). Changing landlords is 
  not a proportionate response.
- **Institution-provided Microsoft 365** — Governed by the college 
  rather than this policy. No sensitive personal data is stored there.
- **Multiple job-hunting platforms** — The same resume data is 
  distributed across 4+ platforms. Risk is accepted during active 
  job search; accounts will be closed after Boss Career 2026 cycle 
  concludes.
